# 单路线回退与精简：0.8.8-fork.1

恢复已交付 `0.8.7-fork.1` 的单路线逻辑和地图显示，包括安全前段、X、未确认虚线。撤回 `0.9.0` 的候选池、额外图搜索、三色地图及动作链候选回调，删除活动目录里的实验模块。地图与场景各沿用原单路线，收集 1.0.9 桥接保留。

## 文件精简

文件增多的主体是防止一次加载大路网卡顿的数据分块，非新增地图。原包约 378 个文件，0.9.0 有 2155 个，其中 1772 个是分帧加载用模块。现在将 base64 字符串块从 256 KiB 合并为 512 KiB，模块降至 951 个，完整包预计 1333 个文件；不删除地图、节点、通道、资源或收集联动。

所有列字节、交互元数据顺序、291 个旧数据块兼容入口均校验原始哈希。旧兼容入口较小，保留它们可维持模块兼容和管理器更新归属。当前管理器按原条目至少一半路径重合识别更新，见 [UE MM 1.6.4 源码](https://github.com/KintaroModding/uemodmanager/blob/v1.6.4/src/UEManager.Core/Mods/ModManager.cs#L2112)；最终以 `verify-package.py --manager-state` 的本机结果为准。

用管理器导入并选择**更新现有导航**，让旧包退场。手动安装先将旧 `PBZQuestRoute` 脚本目录移出游戏，再放新包；直接合并覆盖会留下旧分块。配置路径 `ProjectPBZ/Content/Paks/~mods/PBZQuestRoute.txt` 继续保留，收集 Mod 不动。

## 等效性能优化

- 相同拓扑的丝线复用颜色数组、跳过重复三角索引和颜色计算，预计算六边截面的正余弦。顶点位置和法线继续每次更新，不降低线条采样、碰撞校验或刷新频率。
- 34 ms 更新限制先判断，再读取胶囊脚点；被节流的丝线/审核回调不再重复跨引擎调用。换路线和空中状态仍按原规则处理。
- 继续保留原有分帧路网加载、约 30 Hz 丝线、250 ms 静止近段碰撞缓存，不退回整张图一次阻塞加载。

与原 0.8.7 进行 21 种形状/长度的网格对照，顶点、法线、颜色、索引逐值一致。49 点丝线连续 120 次移动上传，颜色对象从 35280 个降到 294 个，上传次数仍为 120。最大地图的加载模块读取从 519 次降至 267 次；三组交错 Node 样本总 CPU 中位数约 997 → 933 ms，单片峰值样本约 4.5–7.4 → 4.8–7.5 ms。它们不是游戏 FPS，不能据此承诺具体帧率提升。

验证命令见根 README，补充基准：`node tests/benchmark-atlas.cjs <生成目录>`；网格对照：`node tests/compare-fiber.cjs <从旧包提取的 PBZRouteFiber.js>`。结果与完整包校验值记录在 `release/VALIDATION-0.8.8-fork.1.txt`。旧路线的滑坡、屋顶和完整动作覆盖仍需现场验证，此轮不改变寻路判定来换取“性能”。
