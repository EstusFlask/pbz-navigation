# 1.2.3：优先检查动作，避免高差失败候选拖住提示

来源：用户安装1.2.2后的A-01实景复测。安装1364个运行文件逐项匹配，加载日志确认1.2.2。用户报告沿一层楼梯前进时错指，到墙前等待后正确；攀爬后过拐角又错误并要求折返。A-01尚未通过。

## 调度问题的证据与修改

一段日志中，`05:08:34.995Z`先开始原生候选的局部修补，`05:08:51.203Z`报告预算失败，随后才开始动作搜索；约1.3秒后发布带攀爬的前段。该实际顺序说明，走近和等待不能混作同一原因，失败候选修补确实排在动作搜索之前。

受控分帧回归在已存在可用动作的情况下重现：先做昂贵的原生候选修补，会到达30秒墙钟上限而没有机会尝试动作。修改后先验证原生路径；高差超过2米且未通过物理检查时，先尝试动作，再在动作未完成时回退原有步行修补。有效原生路线不受影响，同层路线策略、物理/门锁/楼层检查与预算保留。

```powershell
node --test --test-name-pattern="rejected vertical native candidate|unavailable vertical action" tests/planning.test.cjs
```

原失败回放见`build/vertical-scheduling-red.txt`，通过回放见`build/vertical-scheduling-green.txt`。模拟墙钟从超时变为动作先行，是调度策略验证，不能当作游戏性能数字。独立回归确认动作不可用时仍可走经过检查的步行回退。
