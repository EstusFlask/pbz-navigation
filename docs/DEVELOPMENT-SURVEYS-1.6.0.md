# 地图补采任务 · 1.6.0

日期：2026-11-14（America/Tijuana）。按用户要求独立作为1.6.0，保留1.5.1的A-04动作环修补。开发包新增地图起终点、整段自动记录和本地对照摘要；标准包排除任务表与采集模块。没有安装到游戏或上传。

## 玩家操作

1. 退出游戏，用`dist/Quest_and_Exploration_Navigation_Fork_1.6.0_Development.zip`完整替换旧导航，重启。两种包只启用一份，保留配置。
2. 打开区域地图。绿色为补采起点，橙色为终点，**相同编号是一对**。每张区域图最多显示最近的3对；已采完的任务隐藏并让出下一对。没有连接两点的假想道路。
3. 到熟悉路线的绿色起点附近，落地稍停约1秒。屏幕出现“补采 编号 已开始”，自动选中对应终点并记录；本次规划禁用铃铛中转。无法规划时仍可按正常游戏方式走正确道路。
4. 按正常方式走到同编号橙色终点。错误处可照常按Y保存问题标记，自动关联当前整段记录。不需要定时按Y来保住整段资料。
5. 终点落地稍停约1秒，看到“已保存，等待分析”后结束。告诉助手“补采S012走完了”即可。遇到误走、正确对照或不熟悉路线时补充一句，不必手抄坐标。

中途换目标或长按取消导航会中断保存；重新进入起点可重采。传送跳变、切世界/上下文、超过1秒的采样断档、位置不可取、角色移动停用和已识别乘船/骑乘均中断，保留已观察部分。特殊动作Custom模式照常记录，起终点必须落地。死亡/重载通过角色重绑定、移动停用或位置/上下文变化关闭；没有独立检测所有剧情/死亡事件的承诺。若引擎不提供有效CurrentFloor，采集不会假装触发。

## 保存与分析

- 引擎实际Saved目录：`PBZQuestRoute-survey-<会话>-<序号>.json`为清单，`PBZQuestRoute-surveydata-<会话>-<序号>-<分块>.json`保存整段；每5秒写一个块并更新清单，写后读回匹配才确认。退出前没有收尾时，下一次开发包启动将旧清单标成interrupted，最多最后5秒未提交数据可能缺失。
- 10Hz记录脚点、胶囊、移动模式、实际CurrentFloor及最近地面查询、请求方向和当前目标。独立缓冲保存规划事件、失败胶囊/地面查询、蓝线碰撞和原生候选。最多每秒捕获一次变化后的完整规划/蓝线快照，单块最多两份，另在起终点捕获。快照包含动作连接、条件检查和蓝线接入状态；不声称每帧都有完整蓝线或每个实际动作Actor身份。
- Y案例继续采用前20秒/后5秒格式，并保存`surveyAttempt`，整段块同时记录Y案例ID。高频事件和快照裁剪有显式计数；玩家脚点不作静默抽稀。
- 单段20分钟、240块；每会话最多20次尝试、6400万序列化字符写入量；每文件最多250万字符。字符上限不是磁盘字节数。写失败不计完成，屏幕明确报错。序列化、写入和开发采集有额外开销，没有游戏FPS实测。
- `PBZQuestRoute-surveys.json`只存已采任务及活动报告身份；重启保留已采进度。它不改变路网。需要复测某一段时由作者提升该卡revision，其他卡保持完成，不要求全部重跑。

助手在用户走完后运行：

```powershell
py -3.12 tools/import-development-cases.py
```

原始报告与分块只读复制至`build/development-cases/`，保留原字节、SHA256和缺块说明。引擎UTF-16 BOM报告可直接导入。`index.json`及`SURVEY-REPORT.md`列出行程、移动模式、实际solver/方向、问题标记、被拒原因与裁剪统计。若捕获对应目标的完整规划，另计算长度及后续足点到该折线的三维偏离中位数/P95；这些值用于定位检查点，不能自动判错或证明最短。蓝线离地高度、动作、后续重算和人工绕行仍需结合原始快照审阅。

下一步由助手核对原始点列、实际地面/动作/碰撞与规划/绘制差异，优先修共性规则；确实缺资料才补有向连接。添加有意义的回归后交付新版，在原起点复测。采完、编制、代码通过和当前版本实走通过分别登记；本次没有改变52条资料缺口的已完成统计。
