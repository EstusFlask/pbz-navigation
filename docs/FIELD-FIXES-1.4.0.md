# 反向搜索对照候选 1.4.0

日期：2026-11-14（America/Tijuana）。用户要求制作可试玩的目标端反向搜索版本。基于本地1.3.5，完整包交付；未安装到游戏、未启动采样、未上传Nexus。现场验收状态单独保留。

## 实现

- 默认开启`ReverseSearch`，Mods Menu显示“从目标反向寻路（实验）”；关闭后同一版本切回正向搜索。切换使正在进行的搜索失效并重算当前目标，保留其他设置。无菜单可编辑原导航文本配置，操作见USER-GUIDE。
- 离线路网A*从终点沿实际入边倒推；保留原始有符号边编号，输出仍是玩家到目标的顺序。静态入边索引随路网分帧准备，仅缓存拓扑；溪谷索引约6.43MiB。运行时新增边同步更新入边表，清理时同步移除；门锁、单向动作、落差开关和失败边仍即时筛选。
- 有限步行候选图反查各源点原有的16近邻关系，避免把不对称的最近邻、短落差误当成双向。反向寻找候选链后，仍从玩家起点逐段调用原`world.step`及落差认证；失败有向边在本次请求剔除，成功物理凭证仅在本次请求复用。自定义仅提供`near`而不能枚举完整附近源点的数据源保持正向搜索，并报告实际方向。
- 动作串联图从目标倒推到玩家，候选边仍表示“前一动作出口→下一动作入口→下一动作出口”；近邻目标筛选、完整连接和总预算保留。实际连接检查和安全前段提交继续从玩家端进行。
- 实时局部网格及UE原生寻路接口延用原有实现。本版没有跨请求复用物理凭证或引入增量最短路树。
- 有界远端后缀证明在非流式构造、尚无入边索引时临时使用正向拓扑查询，避免索引准备耗尽原512次推进配额；常规流式路网在加载阶段完成索引。
- 正反向对照发现原离线路网在不一致启发式下关闭节点后不接受更低代价，造成少量路径代价偏差。现允许严格更优的节点重新入队，两个方向都使用该修正；新增独立的可采纳但不一致启发式用例。

## 证据与边界

`node tools/benchmark-search-direction.cjs`生成`build/search-direction-140.json`：

- 17个历史附近步行请求，开放空间物理替身下两个方向均找到15条；均为282次step和1935段35cm几何采样。累计候选图扩展从2292变为2202。两条失败保持候选图不连通。
- 溪谷实际离线图7组非零长度、同强连通分量节点对，两个方向找到相同代价；累计扩展正向180523、反向183429，单路线差异显著，不能据此宣称反向普遍更快。
- 另4组铃铛首锚点在尚未加入现场动作的原始图中均被连通性预检拒绝，双方扩展均为0；这些记录不作为加速证据。
- 本机JavaScript计时和索引准备时间记录在报告内，只表示脱离游戏的CPU执行。未重建游戏碰撞、流送和帧调度，不等于现场出线时间或FPS。

新增回归覆盖有符号反向边、单向不可返、锁/禁边、运行时连接清理、取消索引、非对称近邻、正向物理认证、动作链、开关及不同请求不复用碰撞结果；完整检查结果见`release/VALIDATION-1.4.0.txt`。
