# 1.9.0：碰撞重建与 Recast/Detour 首区域实现

后续状态：游戏已确认禁止WASM生成，当前运行端使用同一核心的普通JS转译。本文记录首版实现；当前版本与失败/修复以[持久项目状态](OFFLINE-NAVIGATION-STATE.md)为准。

日期：2026-11-15。分支 `codex/offline-recast-navigation`。这是本地实验候选，未安装、未上传、未启动游戏验路。先实现旁镇一号路线及周边约 300×250 米区域；**没有完成整个游戏或整个旁镇世界的重建**。历史现场验收不变。

## 实际采用了什么

这一版实际执行锁定的 `recast-navigation@0.44.0` WebAssembly，其中包含 Recast/Detour。碰撞体素化、可走高度过滤、角色半径侵蚀、区域/轮廓/细节网格构建、Detour 走廊搜索与标准 funnel 都交给其核心执行。不是仅借鉴一篇文章后继续沿用原自制路网。[上游 JS/WASM 项目](https://github.com/isaac-mason/recast-navigation-js)、[Recast/Detour 官方项目](https://github.com/recastnavigation/recastnavigation)。

游戏包解码、组件放置、Pawn 碰撞过滤、机关状态、图块存储、调度和蓝线接线仍需本项目实现。把官方核心移植进来，并不意味着能直接把 UE 游戏包丢给它；输入必须先还原正确。

```mermaid
flowchart LR
 A[游戏 IoStore / Cooked 碰撞] --> B[还原组件、实例、地形及世界变换]
 B --> C[按 Pawn profile 与碰撞模式筛选]
 C --> D[固定碰撞与条件碰撞分离]
 D --> E[Recast 分块烘焙]
 E --> F[Detour 图块及门状态变体]
 G[存档字段 / 已加载组件碰撞] --> F
 F --> H[Detour 走廊与贴面路径]
 H --> I[现场地面、锁与胶囊检查]
 I --> J[已确认路段的指引]
```

不新增导航 EXE 或 DLL。新增核心是 CommonJS JS 加内嵌 WASM；图块也是普通 JS 数据模块。保留已有 UE4SS 兼容适配 DLL，仅同步版本号。构建和 ZIP 验证都拒绝 EXE/COM/SCR/MSI。这个约束不等于承诺第三方扫描器绝无误报。

## 从游戏数据还原了什么

本区域索引含 **877 个流送分区及 PersistentLevel**，包括 21 个没有 ContentBounds 但有实际内容的分区。另四个 AlwaysLoaded cell 在 cook 时把 actor 移入 PersistentLevel；已逐项验证，未当成空白缺口忽略。

解码支持普通/样条/实例 StaticMesh、FastGeo、凸体与简单形状、Chaos 复杂三角碰撞、地形高度场和保存的 DynamicMesh。FastGeo 包含实例放置和有效碰撞 gate。父节点模板、非均匀缩放、镜像 winding、Houdini 和相机附件变换均按实际记录处理，未知格式报错。

结果：7,528,008 顶点、13,681,353 三角形；**当前提取器已处理范围内的解析错误为 0**，分区未解释缺失为 0。不能把这句话扩大为“全游戏所有碰撞类型已完整”：骨骼/移动物体、构造时新生成内容、数据层及游戏规则仍有单独覆盖工作。

角色参数为半径45厘米、高192厘米、台阶50厘米、坡度55度，与此前记录的角色物理参数一致。10厘米水平体素，5厘米高度体素；额外保留轮廓误差与体素边界余量，未通过缩小角色来挤过门。

固定几何碰撞 SHA256：`d003b869e8e341fff062ea199b1311e70993cc0ef384bd0bdafdb66f1623b036`。原生序列化 schema 绑定当前游戏二进制 SHA256；安装版本变更时导出器拒绝沿用该 schema。原始包、密钥、存档与研究缓存留在忽略提交的 `build/`，不进入分发包。

## 为什么有墙仍可能撞墙

原有 atlas/极简模型只知道被放进去的面和连接。没有导入的碰撞、错误的父级变换、把单面地板翻面、以点代替角色体积，都会使“地图里有东西”与“规划器知道这是一堵会挡住玩家的墙”不等价。路线点之间再直接画长弦，也可能切入弯道或坡面。

本次实际发现并修正了熟化 Chaos 地板 winding、附着变换、被忽略的常驻/无边界分区等问题。路径高度从 Detour 细节网格逐段采样，不只连接少量转角；最终显示前仍跟随现场地面并检查角色胶囊。

一号路线另外有两种状态问题，不能靠重跑 A* 消除：

- 藤蔓资产默认有碰撞；当前认证存档的 `Broken=true` 会在载入时禁用对应 Vine/Plane 碰撞。必须针对准确 actor 应用状态，不能把同名网格全局删除。
- 至少两扇战斗雾门影响这条路线，其中一扇位于此前漏掉的无边界分区。`Open=true` 存档会恢复消失动画，完成后才关闭 SplineMesh 碰撞。载入动画和战斗变化期间，已加载组件的实际碰撞优先于保存字段。缺失记录不表示开放。

构建器将条件碰撞与固定碰撞分离，在受影响的图块上烘焙开/关组合。本区域有6个条件 actor、480个槽、506种图块状态，去重后501份数据，约26.9 MB原始图块。发行数据不包含玩家当前进度。运行时只读原游戏状态 API；修改状态时先取消旧查询与蓝线，再替换受影响图块。切换角色/世界会清空开放假设。

## 离线结果及其界限

测试起点使用此前记录的铃铛附近实际站立脚点，终点是戏梦山庄正门铃铛。原始行走位置只用于端点及结果对照，未作为道路、连接或几何构建输入。

| 检查 | 结果与范围 |
| --- | --- |
| 全部条件未知 | 返回不完整路径，不冒称到达 |
| 只使用认证存档状态 | 返回不完整路径；起点附近一扇雾门没有保存记录 |
| 显式探索场景：两扇相关雾门开放，藤蔓按存档 | 完整 Detour 走廊，60个拐点，约316.97米；955个贴面采样点 |
| 此前实测脚点对照 | 346/346覆盖，相邻记录断连0 |
| 独立几何检查 | 每25厘米共1,633点，地面支撑/支撑连续性/允许台阶高度以上胶囊体检查失败0 |
| 可移植核心 | 无Node/DOM/fetch的VM可初始化与查询；部分WASM替代接口会安全停用 |
| 真实发行图块与模块 | 门关闭后路线变为不完整，取消旧走廊；开放后恢复；切世界清除状态 |

独立检查用 NumPy 的点/线段/三角形距离，另做下半球竖直接触搜索，不调用 Detour 再证明 Detour。台阶接缝处，中心射线可落到低处，但胶囊仍支撑在边缘，不能把中心射线当成整个角色。该检查不是完整 CharacterMovement 仿真，也未模拟水域、敌人或机关运动。最小上部胶囊轴至碰撞距离约60.93厘米，对照半径45厘米。

**上述完整路线是明确状态场景下的离线候选，不能写成一号路线实机全程通过。** 不需要现在启动游戏来继续导出、烘焙、研究和回归；确认游戏 V8/Puerts 实际启动、场景碰撞与操控表现，最终仍需要游戏内验收。

## 运行时接入与剩余范围

`PBZRouteRecast.js` 在目标和起点都落入首区域时，优先执行新图；该请求不再调用旧 Guides、atlas 或旧路线修补。保留锁与现场物理检查；未加载的远处只交付已确认前缀。其他区域沿用现有导航。首区域本轮仅建立普通步行层，钩索、攀爬、升降梯等特殊动作尚未接到新图。

区域图块按帧加载，状态仅重载受影响图块，查询使用可取消生成器；图变化与世界/角色变化会取消旧走廊。公开数据由不读取存档的 `base` 场景构建，存档解密只用于本地只读诊断；运行时不含解密器、不读取文件存档、不写进度。

下一阶段是扩展完整世界的覆盖审计与分块数据，处理数据层/运行时生成碰撞、更多机关状态、NavArea_Fire代价和水域策略，再把特殊动作接成可验证 off-mesh 连接。当前9个 Fire modifier 未用于代价；水域 Pawn overlap 不当作墙，但水域通行风险尚未建模。因此仍保留 `completeCollisionClaim:false`。

复现命令见 [offline-navigation/README](../offline-navigation/README.md)；原始格式与逐项第一方依据见 [碰撞格式笔记](OFFLINE-COLLISION-FORMAT-NOTES.md)。更早的[可行性报告](OFFLINE-RECAST-FEASIBILITY-20261115.md)描述实施前状态，不能当成本轮完成清单。
