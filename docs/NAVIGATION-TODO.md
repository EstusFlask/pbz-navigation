## 阶段与验收

| 顺序 | 重点 | 需要玩家配合 | 完成标准 |
| --- | --- | --- | --- |
| A | 当前版本闭环 | 上面四张短卡，按需复测 | 已知楼梯/墙体/桥洞/动作问题有明确结论，关键修复经新版本实测 |
| B | 行走与规划通病 | 同层、错层、阶梯、坡道、窄路、洞口等代表案例 | 普通行走不穿墙、不跨层；绕行与重算正确；失败原因和安全前段可信 |
| C | 特殊动作与条件 | 每类先测一个靠铃铛的短机关，再测摆放变体 | 入口、过程、落脚和前后步行连通；方向、能力和机关状态正确 |
| D | 全地图道路与区域连接 | 按区域验证有向关键路段，优先缺口和影响多个目标的连接 | 关键道路和跨区入口有可靠资料，可自动串联，并经长途抽测 |
| E | 任务与收集物 | 用有未收集物品、任务仍可推进的兼容存档 | 选点、实际接近、获取条件、拾取/完成后状态更新正确 |
| F | 未解锁与剧情阶段 | 早期/中期/后期状态档，测试开启前后 | 钥匙、武装、单向门、折梯、升降与剧情限制被正确处理 |
| G | 稳定性、性能与操作 | 固定场景、长时游玩、手柄/鼠标、重载/切图 | 性能有实测依据；无持续错误/目标丢失；新旧功能回归通过 |
| H | 完整版验收与交付 | 按验收矩阵复测，处理剩余重大问题 | 当前游戏版本的目标清单覆盖完成；重大缺陷归零；完整包和验证记录一致 |

B、C、D会交叉推进：补一条道路时发现通病，就先回到B修；动作条件要等其他存档时，保留“待状态验证”，继续能验证的工作。

### B：普通行走与寻路

- [ ] B-01：平地、转角、窄路、洞口、台阶、连续楼梯、坡道与崎岖地面；核对实际角色地面和模组查询。
- [ ] B-02：同XY不同Z、多层房屋、桥上/桥下、山洞/地表；起点、终点、投影和到达都保持正确楼层。
- [ ] B-03：一个障碍、连续障碍、绕远才能接回、封路有侧路、真正封死；每次接回都复验后段。
- [ ] B-04：走路中换层、落地、偏离路线、目标切换、取消；有效前段能继续，过期路线及时失效。
- [ ] B-05：首次加载、未加载远端、搜索超时；区分“待加载/待确认/预算不足/已确认阻挡”，保留可信前段。
- [ ] B-06：比较明显可行的短路与绕路，检查距离和动作代价；人工走法只作可行参照，不当全局最短证明。

### C：动作矩阵

每项都检查“接近入口→执行动作→实际落脚→继续普通行走”，并分别记录可用方向。先测最近、入口明确且玩家熟悉的代表，随后补不同组件/地形摆放。

- [ ] C-01：直上/斜上攀爬、攀缘、翻越和连续动作。
- [ ] C-02：横向跑墙、蹬墙跳、连续蹬跳和立柱连接。
- [ ] C-03：钩索。首个短候选为**后街·窄巷民居二楼旁**；用户已确认确有钩索，待采实际通行与条件。静态约3米距离只作找点参考。
- [ ] C-04：绳索摆荡、滑索、沿绳下降；核对起点、曲线、最终落地和单向性。
- [ ] C-05：梯子上下行、折梯、升降梯/平台各停靠点及运动状态。
- [ ] C-06：短跳落、明确大落差动作、强制滑坡；下降可用不等于返程可用。
- [ ] C-07：动作进行中暂停不适用的地面规划，目标保留，结束后稳定续算；条件不明时提示待确认。

### D：地图骨架与远距离导航

- [ ] D-01：把已有140条工作表连接逐条建立验证记录，分清“有作者候选、已采样、已编制、代码验证、当前版本实走”。详见现有 [缺口表](MOVEMENT-COVERAGE.md)。
- [ ] D-02：先审核已采的worksheet-014/015/016/017资料。只在证明缺几何/连接时补作者数据；先尝试修正可泛化的规划规则。
- [ ] D-03：按当前区域、明确铃铛身份、路线熟悉程度和影响目标数量安排缺口。对不熟悉路线改用更近铃铛或单机关短段，保留探索记录。
- [ ] D-04：验证已有候选和剩余缺口，给每个有向连接标明必要条件。反向只有独立证据后才开放。
- [ ] D-05：庞镇/后街/戏梦等跨world入口，隐藏副本及特殊高度场景，逐一绑定入口、出口和世界身份。
- [ ] D-06：已激活铃铛中转、抵达后末段、未激活铃铛陆路；不让传送替代需要测的道路。
- [ ] D-07：码头/乘船的有效航线，正确暂停、保留目标和下船恢复；剧情强制移动阶段按实际控制状态处理。
- [ ] D-08：自动审计连通与方向，再抽测跨多个已验证连接的长路线。人工验证关键边，避免把所有铃铛有序对逐一重复跑。

已有140条工作表不是整个游戏道路的穷尽清单；收集物和任务测试发现的新支路同样纳入覆盖。当前52条仍是作者资料缺口，四次采样没有自动把统计改成已完成。

### E：物品、任务与备用存档

- [ ] E-00：道路和主要动作稳定后，再准备同平台、同游戏版本、有较多未收集内容的存档。由助手寻找与核对，保留当前存档备份，使用可回退的测试槽位。
- [ ] E-01：固定拾取物、宝箱、屋顶/洞内/隔层目标、可破坏物和环境交互奖励；逐项核对目录点、可站位置与实际获取位置。
- [ ] E-02：手柄十字键/确认、中键/鼠标选点、切图/切层/合并地图；目标ID、XYZ和显示选择一致。
- [ ] E-03：取得物品后的取消/下一个目标、手动取消、离开再回来、保存重载；不残留旧目标或重复报已取物。
- [ ] E-04：敌人掉落、任务奖励、商店或脚本产生等非固定地面目标；提示实际获取方式和前置条件。
- [ ] E-05：任务接受点、进行中目标、交付点和目标阶段变化；不要把任务对象原点当作恒定可到达位置。
- [ ] E-06：远处未加载物品及铃铛中转后末段；切换目标、连续收集和跨区后仍保持正确状态。
- [ ] E-07：按物品类别/地图汇总覆盖，对目录歧义、不可用目标和获取描述逐条核实；采样点数不冒充可获取物品数。

### F：解锁、条件与剧情

- [ ] F-01：钥匙不足、数量足够但门未开、实际开门后；条件和碰撞状态分别验证。
- [ ] F-02：单向门两侧、未放/已放折梯、武装未持有/未装备/已可用、破坏前后。
- [ ] F-03：升降梯在另一站、运动中、故障、开关顺序；提示操作条件与正确等候/接近位置。
- [ ] F-04：任务阶段、战斗封锁、雾门、剧情传送和临时地形；状态变化后旧路径失效、新路径可重新发现。
- [ ] F-05：不同周目/存档状态的代表回归；全解锁存档通过只证明该状态。

### G：稳定性与操作

- [ ] G-01：首次/热加载的路线等待时间、CPU执行与墙钟时间；有条件时记录实际帧时间，比较关闭/开启导航的固定场景。
- [ ] G-02：连续游玩、反复换目标、切图、传送、死亡、重生和重载，检查错误、卡死、内存增长与过期状态。
- [ ] G-03：手柄与鼠标两套完整流程，地图焦点、按键去重、提示/语言和场景线可读性。
- [ ] G-04：收集Mod兼容、启动失败退让、取消同步、配置保留、单副本安装与完整包替换。
- [ ] G-05：把当前可见选项与现用收集Mod的适配对齐，补齐明确欠缺的小地图路线等导航功能；每项说明实测支持范围，使用导航自有组件而不替换收集Mod文件。

### H：可以称为“完整”的条件

- [ ] H-01：当前游戏版本的地图、任务/收集类别、主要交通和动作矩阵已经枚举并逐项有结论。
- [ ] H-02：关键有向连接和条件覆盖完成；未知、未采和未复测条目清零，剧情阶段按明确行为验收。
- [ ] H-03：没有未解决的崩溃、状态破坏、穿墙/危险错层、已知可达却长期缺路等重大缺陷；普通延迟与体验问题有实测和结论。
- [ ] H-04：从首次进入区域直接选目标、途中过渡、真实获取/完成、保存重载均通过代表回归；正确对照不退化。
- [ ] H-05：代码、真实模块、实景和性能证据分开记录；版本、完整包与说明一致。公开发布由用户明确安排。

完成度按这些验收项和验证台账计算，不按发布版本号、测试数量或“原生寻路返回成功”计算。游戏更新后，对受影响项重新验证。

## 每轮协作规则

1. 助手先看当前任务、上一轮证据、安装/加载版本；建立新会话，确认新采样、导航日志和Y标记都在线。
2. 给玩家一张卡：目标、出发铃铛、目标铃铛/物品、预期动作、检查点与停止条件。路线身份先核对；上次已完整采集的长路优先只复测问题短段。
3. 玩家按正常游戏方式前进。问题处靠边站定单按Y，停两三秒；误按直接说明，由助手改为正确对照或待确认。
4. 玩家不熟路线、入口不清或持续摸索时，停止这条卡，换近处铃铛/单机关或先查资料；探索不自动写成已走通连接。
5. 助手把失败分成规划/几何、支撑碰撞、错层、动作入口、条件、加载、预算、显示和目标状态，尽量找共性；同一原因影响多处时先修共性。
6. 能复现时先建失败回归，再修代码、跑相关与必要完整检查、交付完整包；缺资料的具体条目保留待采状态。
7. 新版回到同一个原起点直接选目标复测。通过才关闭问题，并更新台账的版本、方向、存档状态和证据；只走过或只代码通过分别记账。
8. 玩家说本轮结束时，停止全部采样/按键监听并核对，归档原始记录和摘要；下次从activeCase继续。

每轮默认1—3个短案例，预留修复/核对时间。采用当前全解锁档推进A—D；需要首次拾取、未开启或剧情中间态时再切换测试档。无需现在更换存档。
