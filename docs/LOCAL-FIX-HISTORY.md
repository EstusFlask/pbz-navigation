# Quest Navigation 本地修补

`Quest_Navigation_0.8.5` 可以直接修改：入口、寻路、碰撞、红绳绘制及兼容层都是可读 JavaScript。地图路网与表面数据也在包内，但没有附带其生成工具。`Map_Collectible_Tracker_1.0.9` 的入口可读，其他核心模块大部分是封装的 Lua 5.4 字节码。

本地补丁标识：`0.8.5-local-fix5`。这是在现有包上的修改，不是作者发布的新版本。开发和安装范围只有导航 Mod；收集 Mod 的原始文件保持不变。

## 已处理

- **fix5 绕石头与 X 预览**：不再因为一个局部障碍丢掉整条路线。先在障碍附近寻找绕行并重新检查拼接后的路段；搜索期间就显示大地图已确认前段、受阻 X 和未确认虚线。找不到绕行时保留此预览，场景丝线只到已确认安全的位置；向前移动、绕过障碍或通道状态改变后重新搜索。
- **fix5 地形与物品端点**：局部行走/验证范围由 90/65 米提升到约 120 米；修正稀疏路径的直线高度插值把起伏地面误判成换楼层。小石头边缘可检查胶囊脚下的邻近支撑，仍保留身体碰撞检测。物品导航可选择同层交互范围内的站位，避免强求走进物品自身碰撞；关门等遮挡不会当作物品碰撞忽略。
- **fix5 动作链**：旧回退遗漏普通静态通道，而且只能尝试单个动作。现在以已识别的梯子、攀爬、抓绳/钩索、滑索、沿绳下降和升降通道连接已检查的步行段，支持连续多个动作，保留方向与折梯解锁限制；选择目标时补充读取附近已加载的实际入口/出口。修正新发现的固定梯子被一律当成未解锁折梯的问题。

- **fix3 中键追踪收集图标**：fix2 的中键只识别旧版 JS 图标，1.0.9 图标会退回二维地图落旗，可能落在楼下。fix3 从 1.0.9 的原始选择服务同步悬停物品，用实际图标投影位置校验命中后保留其三维坐标，并通过原选择服务追踪。左键追踪继续同步；取消追踪也会停止导航。
- **fix4 可行路线**：原生“完整路径”与离线路网都先检查地面支撑和角色胶囊碰撞，不能通过墙或楼板的候选会被拒绝。楼上、楼下、同层目标都可进入附近的实景搜索；同时使用原生路径的门洞采样，减少粗网格错过窄门的问题。删除已知不通路线的回退/复用，避免连续重算同一堵墙。
- **fix4 路径长度**：局部 A* 使用实际三维路径长度和欧氏距离下界，移除原来的高度加权偏置；目标节点出队后才确认结果，并与已验证的原生候选比较。独立 Dijkstra 校验场景中，旧搜索选了约 10.38 米，新搜索得到可行最短的约 7.92 米。
- **fix4 丝线聚团与入地**：完全停用原生拖尾粒子，以当前帧的细线网格替换旧几何；转身不保留过去的粒子轨迹。末端从地面下 13 厘米改为上方 10 厘米。头段逐帧检测实际绘制折线，不再检测一条近似曲线后另画一条。

- **红绳远段穿墙**：原先红绳自身的碰撞检测只覆盖角色前方约 10 米。补丁把远段也纳入检测，每次最多追加 12 次探测，并检查 2 毫秒的分帧预算。远段绘制使用已检测的折线；碰撞处停止绘制。动态障碍会定期复查。
- **红绳更新开销**：重塑及路线碰撞审计分别限制为每 16 毫秒最多一次；网格直接使用已检查的样本，去掉样条坐标回读和不必要的样条重塑。
- **1.0.9 收集目标同步**：原导航只适配 JavaScript 版 Map Tracker Plus 0.6.7，与 UE4SS/Lua 版 1.0.9 不能直接通信。新增两端适配，将 1.0.9 的手动目标、自动追踪目标、收集完成和取消事件送给导航；导航取消也会通知收集 Mod。取消命令校验会话、目标和修订号，过期命令不能清除新目标。

## 范围与限制

桥接脚本和原生入口组件都放在导航拥有的 `platform/steam/ue4ss/Mods/PBZQuestRouteCompat/` 下，通过 UE4SS 启动事件在运行时连接收集目标服务，不替换、复制或修改 `PbzMapTracker` 目录。原版收集 Mod 无需更换。

原生组件针对当前 UE4SS `v3.0.1-1195-g1ceefac8` Shipping 版本及原版收集 Mod 1.0.9 构建，启动时验证两者的文件校验值。其他版本会停用收集联动，基础任务/落旗导航仍可使用；状态记录在导航桥接目录的 `PBZQuestRouteCompat-status.txt`。

- 11 个世界的静态路网数据没有重新生成。实景校验会修正导航点与实际地面的小幅高度偏差，修复行为仍需要在用户截图位置复测。
- **1.0.9 已适配的是目标导航与取消同步。** 旧 0.6.7 适配层中的小地图路线叠加、放大图标及自动饰品提示没有迁移到 Lua 版；导航设置里的对应选项对 1.0.9 不生效。1.0.9 自身的小地图、图标和追踪功能仍由它管理。
- 检查了真实 Lua 1.0.9 目标模块与 JavaScript 导航接收器之间的文件通信，但未启动游戏验证 UE 原生碰撞、输入钩子、地图界面或帧率。不能据此承诺实际 FPS 提升幅度或完整游戏兼容。
- “最短”适用于找到完整解的离散采样图，不是整张游戏地图的数学全局最短保证。局部搜索有范围、节点与时间上限；若预算耗尽，优先保留已检查的候选或带 X 的诊断预览，不宣称整个目标不可达。普通行走边会检查沿途支撑、步高和胶囊碰撞；攀梯/升降等使用动作连接和专用入口/出口验证。
- 原生/离线路线默认验证角色周围约 120 米的连续段；更远处保留已检查的前缀并标记未完成。诊断路线的大地图后段为未确认虚线，不允许场景丝线跨过受阻处。如果连起点附近的安全前段都不能确认，场景丝线仍会隐藏，但已有的 X 预览会保留。
- 动作链只覆盖已识别的通道数据和已加载实例，不是自动操作角色的功能。到梯子、钩索或升降装置入口后，仍由玩家用游戏原键执行动作。残偶谷底齿轮与三楼点位尚未现场实测，不能声称整关的全部特殊通道已验证。
- 丝线依赖游戏的 ProceduralMeshComponent 和可用材质，提供多个材质候选；若渲染能力缺失会记录具体错误并隐藏丝线，不会再退回会聚团的粒子效果。地图导航仍可使用。

## 安装补丁

完整包：`dist/Quest_Navigation_0.8.5-local-fix5-navigation-only-full.zip`。内含全部导航脚本、路网、图标和导航自己的桥接组件，可以替换原导航；包内没有收集 Mod 的文件。上一版 `local-fix1-patch.zip` 是增量包，不再用于管理器导入。

1. 退出游戏，保留管理器里现有的 Map Collectible Tracker 1.0.9，保持启用。
2. 把新的导航完整 ZIP 拖入 UE Mod Manager。保留导航游戏文件及 `PBZQuestRouteCompat` 两部分的勾选。
3. 管理器应识别为更新原 Quest Navigation，确认更新后启用导航。不要同时启用另一份旧导航。
4. 不要导入旧的增量包，不要替换或停用收集 Mod。若之前已手工应用过 fix1 对收集 Mod 的改动，应先恢复官方 1.0.9；按已检查的当前管理器记录，用户安装的收集 Mod 是原版。
5. 导航继续由 PBZModLoader 加载，导航自己的桥接组件使用现有 UE4SS。包内没有加载器或 UE4SS 本体，无需替换它们。
6. 重启游戏，在收集 Mod 中选择目标，检查大地图路线、场景红绳、切换目标、完成收集和取消追踪。

### 键位

- 1.0.9 收集物：左键图标追踪；fix3 也支持鼠标悬停到图标后按中键，以相同物品的三维位置导航。手柄仍用 A。
- 地图空白：中键落旗，按地图选路面；它不代表该位置楼上某件物品。
- 取消导航：在空白处长按中键约 0.6 秒；1.0.9 原生取消追踪也会同步停止。
- 场景丝线要在关闭地图后查看，`WorldThread` 需开启；`Sense30` 模式需先使用洞照感知。

不要同时保留旧 JavaScript 收集 Mod；按 1.0.9 原说明移走旧 `pbz-map-tracker` 目录。这里没有复制或覆盖实际游戏安装目录。

联动文件保存在游戏实际 Saved 目录：`PBZQuestRoute-tracker.json` 和 `PBZQuestRoute-command.json`。它们是临时状态，不是存档。日志中出现 `UE4SS Map Tracker target adapter active` 表示导航已连接。

撤回时用管理器恢复原导航或移除新导航，收集 Mod 不需要恢复或重装。这里没有改动实际游戏目录或管理器数据。

## 本地验证

```powershell
node --test tests/navigation.test.cjs tests/planning.test.cjs tests/passages.test.cjs tests/tracker.test.cjs
python tests/run-lua-tests.py
python native/build-native.py --ue4ss "现有 UE4SS.dll 的路径" --test
python tests/build-patch.py
```

Lua 检查需要 Python 的 `lupa`，并明确使用其 Lua 5.4 运行时，或用 Lua 5.4 执行 `tests/tracker-bridge.lua`（需将收集 Mod 的 Scripts 目录加入 `package.path`）。

回归覆盖远段墙体、动态障碍复查、远段探测预算、重复重塑、样条回读、审计节流、目标同步、无效/过期状态、自动提示、断连恢复、过期取消、心跳与停止。另有真实文件往返：Lua 1.0.9 目标 → JSON → JavaScript 导航 Tracker → 取消命令 → Lua 1.0.9。

fix2 还检查独立桥接入口、require 恢复、重复加载、原生 ABI 布局、文件校验门限及启动分派。原生测试使用隔离测试接口，不等同于游戏内加载测试。

fix3 增加三层楼梯寻路、楼下局部路径拒绝、搜索预算、短样条粒子关闭与清除、短样条采样、Lua 图标命中以及原始 1.0.9 悬停/选择 API 检查；文件往返也覆盖中键选择上层物品后高度保留。

fix4 共 33 项 JavaScript 回归，新增原地转身无粒子、实际绘制段与碰撞段一致、末端不入地、洞口/高台拒绝、低桥下楼层保持、埋地路网点修正、原生受阻路线绕行、较短可行路径比较、上下楼梯、窄门和 Dijkstra 最优长度对照。另检查 Lua 联动及原生入口构建。这些检查不等同于游戏现场验证。

fix5 共 46 项 JavaScript 回归；新增约 93 米路线绕石头、搜索早期保留 X、失败后保留预览、物品碰撞附近站位、交互距离、起伏地面、固定梯子识别、多动作串联、反向与单向约束、升降梯接滑索，并通过主导航入口验证梯子接抓绳。另保留真实 Lua 1.0.9 文件往返测试。运行日志用 `[blocked preview]`、`[partial]`、`[complete]` 区分结果，预览不代表已找到完整路线。

原生组件使用固定 UE4SS 提交 `1ceefac8b8c286f0fb3eb62b4aae075ff81df0bd` 的公开接口构建，编译器为 MSVC x64 Release/MD。[UE4SS 启动事件接口](https://github.com/UE4SS-RE/RE-UE4SS/blob/1ceefac8b8c286f0fb3eb62b4aae075ff81df0bd/UE4SS/include/Mod/CppUserModBase.hpp)。完整导航数据也使管理器可以按其“至少覆盖原条目一半文件”的规则识别更新。[管理器 1.6.4 更新识别规则](https://github.com/KintaroModding/uemodmanager/blob/v1.6.4/src/UEManager.Core/Mods/ModManager.cs)。
