# 已撤回：0.9.0-fork.1 多路线记录

用户反馈效果不佳，现已回退到 `0.8.7-fork.1` 单路线逻辑，并以 `0.8.8-fork.1` 精简优化包交付。以下为历史记录，不代表当前源码。历史安装包保留；未提交的实验源码与测试另备份在 `build/reverted-multiroute-source.zip`。

已接入正式源码。`PBZRouteAlternatives` 保存原生/离线路网候选和动作链前段；`Ink` 仅绘彩线，完整主路线出现时自动收敛为一条。候选有几条显示几条，最多三条，不以重复走廊凑数。相同动作链的较长前段更新同一候选，不增加重叠线。

候选快照统一标记 `mapOnly`，不赋给 `S.trip/S.line`，不用于到达判定或场景审核。已检查的攀爬/钩索前段可保留最后尚未确认的目标连接，仅供地图查看；它不是已验证可行的完整路线。此功能没有解决所有滑坡或通道漏判。

额外图搜索只在地图显示当前区域、主规划空闲且没有完整主路线时运行；每片目标 0.75 ms / 最多 8 次生成器步骤，间隔 34 ms，总时限约 6 秒 / 最多 6 次查询。主规划抢占时取消后台迭代，图权重不改写。地图投影同样分帧，每次绘制最多 16 步和约 1.25 ms；已完成的候选投影不因场景审核版本变化而全部重算。原始路网与收集 Mod 文件不变。

本地 97 项 JS 回归覆盖三条/一条切换、无文字/X、场景状态隔离、动作前段、候选去重、投影缓存与预算、实际日志坐标路网回放。游戏内画面和帧耗时仍待复测。以下保留此前探索依据；原型只是设计来源，正式运行不依赖 HTML。

## 此前探索

结论：可实现。按用户最新偏好，优先做**未找到完整路线时，地图显示最多三条；找到可达路线后只显示一条；场景保持一条**。多路线层只绘不同颜色的线，不新增文字、编号、图标、状态或 X。`未找到` 包括预算耗尽和加载不足，不等同于已证明不可达。

交互原型可双击 `dist/Navigation_MultiRoute_Prototype.html`。原型源代码、实验数据和截图保存在 `codex/prototype-multiple-routes` 分支的 `prototypes/multi-route/`，提交 `372b610`。

## 正式接入需要的改动

1. **保留候选**：`PBZQuestRoute.makePlan`、`Transitions.route` 当前找到一条就返回；`setTrip` 也只保留一个 `S.trip`。增加按目标/世界/目标位置版本隔离的候选池，同时收集步行绕障、离线走廊和攀爬/钩索动作链。最多三条明显不同的走法，有几条显示几条。
2. **保留判定信息但不绘制**：碰撞阻断、通道锁定、现场未加载、楼层不匹配、超时分别留在内部。未知支撑不应直接成为整条动作链的永久否定；确认的墙壁、关闭的门和单向动作继续约束搜索。玩家移动时重新检查起点接入，避免把旧站位上的线直接当成当前路线。
3. **滑坡单独处理**：`Ground.step` 目前主要检查支撑、法线、步高和胶囊，不能证明所有几何合格的坡都可向上走。需核对游戏实际的滑落状态、滑坡对象/体积、物理表面等信息，记录有方向的失败边。不能通过统一放宽坡度来修复，也不能把所有坡道上行都封掉。
4. **地图显示**：`Ink` 已有分段绘制、着色、投影与缓存能力，可接候选集合；颜色绑定候选身份，排序改变时不乱换色。共用前段合并，分叉后分色，避免三个几乎相同的线叠成一团。主线收敛为一条后停止额外搜索与重绘。
5. **预算**：失败后才追加候选，优先在打开地图时生成/投影；共享总搜索时间、场景查询与缓存，不跑三套完整寻路。`Graph` 的 A* 临时数组由一次规划占用，不可随意并发交错运行多个图搜索。场景仍只更新一条丝线，保持既有更新上限。
6. **如后续需要场景三条**：`PrivateRibbon/Fiber` 能扩展为不同颜色，但当前材质参数和顶点色都写死红色，需要一起改；三条也必须共用碰撞与网格上传预算。仅增加三个 `Threads` 实例会重复查询、增加组件/顶点上传，不能当作低成本实现。

现场重点验收：同一目标保留不同走法；重复走廊不凑数；成功时收敛一条；失败不清空候选；换目标清空旧候选；包含多次攀爬/钩索的已检查前段可以留在地图中。滑坡上行的准确判定、完整动作链覆盖，以及游戏帧耗时和地图打开耗时，仍需独立验证。
