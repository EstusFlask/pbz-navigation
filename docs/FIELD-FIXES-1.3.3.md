# 下梯动作线几何修复候选 1.3.3

来源为1.3.2现场A-02。用户确认原地重选后木板到第一处下梯入口这段正确，但下梯指向不准确，并提供截图。截图中蓝线在平台内先向上形成尖角，再向下穿入木板，未明确对准可见梯子。

## 核对依据

- 会话：`build/field-live-1.3.2-20261114-42804-A02`，第二次Y位于第一处下梯入口，用户图片保存在`ladder-entry-user.jpg`。
- 同一会话只读提取真实梯子组件，见`first-ladder-native-components.json`，未执行游戏函数或写入游戏内存。
- 组件属于`BP_SpecialMove_ClimLadder_C_UAID_BCFCE7058A98248502_2075694031`。根位置约`(-59778.431,216416.581,-13538.276)`，偏航111.505度。
- 上交互碰撞框本地位置为`(200,0,4175)`，上梯子模型组件为`(0,0,4075)`；碰撞框中心离模型轴线200厘米，并高100厘米。实际已检查的上落脚点约`(-59851.750,216602.656,-9467.224)`。
- 原动作线使用碰撞框中心，并仅向上修正埋地锚点，导致高于落脚点的碰撞框中心保留在动作点列中。由此产生平台内的上尖角与偏离模型的下降段。

## 修改与回归

已加载梯子保留原交互路径供落脚、方向、解锁和入口检查；另从同一Actor的原生Top/BottomMeshComponent或同名场景组件取得梯子模型轴线。仅当轴线端点有效、且分别距对应交互端点不超过6米时用于动作引导；缺少模型资料时回退原交互路径。

梯子动作按已检查落脚高度修正端点，可向上或向下校正，保留模型的XY轴线；动作组合分别连接交互落脚点、模型上端、模型下端和出口。其他动作的埋地锚点规则保持。没有增加未验收的通行边、反向开放或碰撞例外。

`tests/passages.test.cjs`的新回归通过真实加载→动作规划接口复现“升入交互框再下降”：修改前记录在`build/ladder-guide-red.txt`，修正后为`build/ladder-guide-green.txt`。保留落脚点不变，并断言动作无向上尖角、下降段对齐模型轴线。测试以该几何关系构造精简场景；不是当前游戏完整碰撞或最终渲染的回放。
