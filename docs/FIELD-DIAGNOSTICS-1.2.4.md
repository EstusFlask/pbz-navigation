# 1.2.4 本地定点诊断候选

本版补足A-01定位所需记录，保持现有寻路行为、目标XYZ和安全检查。**它不是已解决入门错指的修复版。** 1.2.3本轮实测仍未通过，监控已停止。

## 本轮已确认

- 用户在进门后、还没上楼梯时就发现方向错误并按Y，不能把它记为楼梯转角或爬墙后的问题。
- 在同一位置取消并重新选择同一个塔顶目标，等约10秒仍错；单纯沿用门外旧起点不足以解释。
- `Bell_NLES_012`目标XYZ已与驻留铃铛核对，误差约0.464厘米，保持原值。
- 已有日志显示低层候选受到身体碰撞拒绝后仍保留引导前段；但未捕获原生对象的完整状态，不能据此认定它是部分路径还是包含未解析动作的完整路径。

## 下一次诊断区分什么

1. 若原生返回的是低层部分路径，新记录应显示`native query: partial`及其低层终点，与高层目标并列。由此检查追加目标形成候选和发布前段的策略。
2. 若原生返回完整路径，但点列中跨层段需要动作，新记录应保留其原始首尾点列和完整状态，再核对动作边界转换。
3. 若单个入口连接占住分帧搜索，新记录应指出它的起终点、动作身份、执行/墙钟耗时；总任务超时取消时，仍能看到`action connector interrupted`。

原生点列最多记录32点：短路径完整保留，长路径保留首尾各16点并标明截断和原索引。普通连接开始/结果明细限前16个，后续慢连接与所有中断另记。原生API拒绝状态和直接回退候选分开记录，避免把合成点当作引擎输出。

正式验路拒绝发生时，另记录命中组件/Actor、简单或复杂碰撞、实际碰撞类型、组件与玩家的响应。描述在拒绝边界才读取；响应差异只记作证据，仍保留原碰撞判定。失效或不可读取的对象不会因诊断而中断寻路。

## 下一张卡

关闭游戏后安装1.2.4，仍用当前存档。优先站在已知错误的门内位置；如果从铃铛出发，只需先到门内。助手确认新日志和采样后，原地选择一次“溪谷杀气塔顶”，不移动、不反复重选；等这次计算结束或30秒。错误可按一次Y，之后继续站定。无需重跑整条路。
