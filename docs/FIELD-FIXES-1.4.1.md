# 杀气塔顶货币钩索与菜单修复 1.4.1

日期：2026-11-14（America/Tijuana）。基于用户安装的1.4.0，1375个运行文件与完整ZIP一致，加载日志明确为1.4.0。用户报告菜单无开关、杀气塔顶附近货币在钩索使用前无路线，使用后才出线。

## 根因与修改

1. 1.4.0只注册了旧Mods Menu的`ReverseSearch`，导航自己的PbzModConfig提供器只有绳子颜色。实际提供器回归直接失败，错误为`the actual PbzModConfig navigation provider has no reverse-search toggle`。1.4.1在PbzModConfig新增“路线规划”组及切换项；颜色组与导航组分别重置，保存、重启、真实远程主机协议和Lua→JSON→JS读取均覆盖。
2. Lua使用`GetProjectSavedDirectory()`，本机实际为LocalAppData下的Saved；JS旧代码固定读安装目录的`Content/../Saved`，本机该配置文件不存在。新回归复现“菜单保存但JS仍为默认值”，现两侧都使用引擎Saved路径，接口不可用才沿用旧路径；部分写入保留上一有效值。PbzModConfig中的显式布尔值优先，未保存该项时兼容旧Mods Menu/文本设置。
3. `BP_GapBlocker`的`TriggerSphere`是较大的检测/瞄准区域，现场与`GrabPoint`同心，中心在上层。旧代码优先它作为步行入口；实际可站的下层起跳区由`TriggerBox`给出。新版本优先取有效TriggerBox，缺少时沿用球体入口；GrabPoint仍为动作中间的固定世界抓点，LandArea仍为落点。只将动作两端接地，不以端点高度插值移动空中抓点；交互条件、身体/地面检查和单向性保留。

## 回归与限制

`tests/fixtures/tower-hook-currency-20261114.json`保留现场位置；`node --test --test-name-pattern="captured tower hook" tests/passages.test.cjs`在修改前以`no route exists until the player has already used the hook`失败。只改变入口选择后完整路线恢复，另修正动作显示的抓点偏移。检查完整链、固定抓点和条件不满足时仍拒绝。

测试使用替代的地面/步行回调，不重建游戏碰撞；它证明当前通病的代码路径被修正，不等于1.4.1已经游戏走通。完整JS/Lua/原生/包校验记录见`release/VALIDATION-1.4.1.txt`。
